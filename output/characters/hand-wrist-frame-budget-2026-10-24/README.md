# 手部腕部缓存：未采用的性能实验

2026-10-24，基于 `1835b2b`。本单元只保留诊断记录，实验源码已撤回，正式游戏仍为 `index-BbnkcfNs.js`。没有新的浏览器 FPS 测量、性能提升发布或 60 帧验收；Render 保持撤下，42 组电影质量完成数不变。

## 目的与范围

上一轮浏览器诊断把人物更新列为主要成本之一。本次尝试复用握姿不变、只有手腕转动时的手掌/手指表面，保留腕部接缝的完整计算、全部顶点与骨骼。测试使用实际 GLB 和人物动画，在独立的原 HEAD 副本执行；没有改写主存档或重启主服务。

这是单个人物动画的 Node CPU 测量，不含绘制、浏览器调度和网络，不能换算为游戏帧率。每次运行 7 轮、每轮 318 帧，舍弃前两轮，共计 1,590 个样本。后台负载未完全隔离。计时脚本沿用前一轮手部基准，覆盖墨菲斯完整红衣女子讲解动作。

## 结果与撤回理由

| 顺序 | 动画均值 | P95 |
| --- | ---: | ---: |
| 原版 1 | 3.432 ms | 5.059 ms |
| 延迟缓存实验 1 | 3.354 ms | 5.050 ms |
| 延迟缓存实验 2 | 3.474 ms | 5.327 ms |
| 原版 2 | 3.543 ms | 5.203 ms |

两轮均值汇总为 3.487→3.414 ms，约 2.10%，结果重叠且 P95 没有改善，不能认定稳定收益。更早的逐次建立缓存方案反而较慢，见 [benchmark-eager.jsonl](benchmark-eager.jsonl)；上表原始数据见 [benchmark.jsonl](benchmark.jsonl)。

另用独立的调用计数运行检查缓存实际使用情况，计数不混入上表计时：

| 318 帧场景 | 单手变形入口调用 | 新表面缓存复用 | 新表面缓存建立 |
| --- | ---: | ---: | ---: |
| 墨菲斯讲解 | 223 | 59 | 1 |
| Neo 行走，速度 3.3 | 2 | 0 | 0 |
| Neo 奔跑，速度 7 | 352 | 0 | 0 |

行走已被现有完整姿态缓存处理，新缓存没有额外收益；这段奔跑中的手指姿态持续变化，也没有命中。实验仍为每个角色增加约 0.71 MiB 法线系数暂存；墨菲斯本次实际建立的单手表面再占约 0.84 MiB，绑定拓扑另增约 0.52 MiB，拓扑可由同一源几何的角色共享。这些只统计新增数组，不是游戏总内存。见 [cache-utilization.jsonl](cache-utilization.jsonl)。

因此撤回本实验，避免用额外内存和维护成本换取尚未证明的整体收益。后续应优先检查实际变化中的握姿计算、可见人物更新和阴影提交成本，并以真实浏览器连续行走、战斗和切场验证。

## 验证与边界

- 原有相关测试修改前 5/5，恢复原版后再次 5/5。
- 新预算回归在原版先失败：一次双腕更新读取 13,346 个法线分组；实验中接缝路径降为 472，内侧法线仍需解析修正，不能表述为只更新 472 个法线。
- 初版直接缓存法线导致两项精度回归失败。补足 Float32 权重总和不严格等于 1 的平移修正后，最终候选相关 7/7，包含 24 次连续腕部旋转、位移、非均匀缩放的完整皮肤对照。
- 最终候选没有执行已准备的 256 姿态新旧数值对照、全仓测试、生产构建或实机游玩验收；由于收益不足，提前撤回。不能把局部 7/7 说成完整质量验收。
- 一次工作目录错误造成旧源测试失败，另一次诊断脚本首次未创建成功；纠正路径后重新运行。错误源日志不作为候选结果。

实验源码、补丁、试验测试及未执行的对照脚本仅留在本机此目录，不在运行时或正式测试目录。当前提交只收录测量结果、有效测试日志及文档。原有 11 份工作区实验、800 份编译产物哈希保持，1,247 份候选输入恢复。正式 5173 服务 PID 83388、HTTP 包内容及 SHA256 保持，5200/5201 无 QA 服务。主入口已在侧栏确认可用并保留。见 [verification.json](verification.json)。

60 FPS 仍意味着约 16.7 ms 的整帧预算；尚无经验证的最低硬件配置。存储容量主要影响资源容纳，内存不足可能造成换页卡顿，CPU/GPU 工作量和实现效率决定常态帧时。本次结果不能证明购买更多内存即可解决问题。已有浏览器测量范围见[上一轮性能基线](../red-dress-frame-budget-2026-10-24/README.md)。
