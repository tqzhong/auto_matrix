# 可选渲染画质与帧率实测

2026-10-24，基线 5fd29dd。新增精致、均衡、流畅三档，仅调整 3D 渲染分辨率。默认精致沿用原先最高 1.5 倍设备像素策略；均衡最高 1 倍且不超过 1920×1080 像素，流畅最高 .75 倍且不超过 1280×720 像素。HUD 使用原来的 CSS 分辨率。人物、几何、动作、灯光、阴影及全部后处理保留，没有新增依赖。

窗口变大时重新计算像素预算；切换同时更新主画布、合成缓冲区、遮蔽、泛光和 FXAA。选择立即生效并保存在本机浏览器；存储不可用时仍应用设置并提示刷新后需重选。菜单打开时清除移动输入，Esc、关闭按钮和点击背景均可返回。

## 为什么先做这个

目录最初用于验证蒙皮包围盒开销。实测所有角色包围盒合计每帧约 .61ms，因此没有改写包围盒算法。完全跳过动态阴影的诊断只有约 33fps，随后恢复阴影。分辨率实验收益更明显，最终交付的是用户可选的清晰度与流畅度取舍，不是同画质下声称翻倍优化。

60fps 意味着帧间隔约 16.7ms。CPU 的人物/世界更新、渲染提交，GPU 的像素/阴影/后处理，以及浏览器调度都会影响它。磁盘容量主要影响存放和加载；内存不足可能引发卡顿，但本轮没有证明容量是主要瓶颈，也没有足够的跨硬件数据制定最低配置。

## 实测范围

Apple M3、24GB、Codex 内置浏览器。暂停的飞船床边镜头，预热 3 秒、采样 15 秒，不录屏、不插入 GPU 查询、不同时构建或运行测试。CPU 提交计时不等于独立 GPU 耗时。

| 样本 | 实际渲染尺寸 | FPS | P95 帧间隔 |
| --- | --- | ---: | ---: |
| 原型高分辨率基线 | 1920×1080 | 28.46 | 50.4ms |
| 原型中分辨率 | 1280×720 | 47.77 | 31.0ms |
| 原型低分辨率 | 960×540 | 58.60 | 21.5ms |
| 原型恢复高分辨率 | 1920×1080 | 27.91 | 50.2ms |
| 正式设置流畅 1 | 960×540 | 58.07 | 22.4ms |
| 正式设置精致 | 1280×720 | 46.26 | 32.6ms |
| 正式设置流畅 2 | 960×540 | 60.02 | 19.3ms |

浏览器窗口覆盖操作改变了设备像素比，最后三项在设备像素比 1 下测试，所以“精致”实际为 1280×720；不能与早期 1080p 混作同画质对照。三项正式设置的阴影均为 287 次提交、926667 三角形；最后一项全场景多出 2 次提交、256 三角形，保留差异而不声称画面几何逐项完全相等。没有对运动或战斗做完整 FPS 采样，P95 也没有稳定落在 16.7ms 内，**不接受全程稳定 60fps**。

完整相机、尺寸、帧间隔、提交和 CPU 数据在 [汇总](performance-summary.json) 与 [压缩原始报告](raw-profiles.json.gz)。临时计时和分辨率探针已移出候选源码；原始探针文件仅在本地保留。
