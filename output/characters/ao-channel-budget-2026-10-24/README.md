# 接触阴影单通道缓冲：保留采样与分辨率的小幅优化

2026-10-24，基于 `8d2dec6`。本机正式入口 <http://localhost:5173/> 已更新为 `index-CCOTDEXi.js`；Render 保持撤下。没有达到稳定 60 FPS，42 组电影质量验收完成数不变。

## 改动

GTAO 与降噪输出都是灰度。把这两个中间缓冲从 RGBA16F 改为 R16F，读取时复制红色值到 RGB；场景颜色、法线、深度、模型、纹理、AO 分辨率、8 次 AO 采样、16 次降噪采样和混合强度保持原设置。调试输出仍正确区分灰度 AO 与彩色法线/场景。

1920×1080 时，两个缓冲的逻辑颜色存储合计减少 24,883,200 字节，约 23.73 MiB；这是格式与尺寸推算，并非实测驱动显存分配。正式 JS 增加 1,085 字节，无新游戏资产或依赖。

开发面板增加四通道对照开关及独立的无损帧导出按钮。无损导出在渲染完成回调内读取实际 canvas，通过既有本机录像接口保存 PNG；采样和录像期间不允许导出。面板仅在 Vite 开发模式及 `?profile` 下加载，正式包没有这些控件。

## 实际帧率

Apple M3 / 24 GiB，Chrome，实际缓冲 1920×1080、DPR=1。使用上一轮真实广场游玩检查点的独立副本；原生继续 Neo、继续世界时间，固定镜头，按四通道→单通道→单通道→四通道顺序测量。每轮预热 3 秒、采样 15 秒，不录屏、不构建、不同时运行另一游戏画面。

| 报告 | FPS | 帧间隔 P95 | 绘制次数/帧 |
| --- | ---: | ---: | ---: |
| [四通道 1](rgba-cpu-1.json) | 27.48 | 48.20 ms | 332 |
| [单通道 1](scalar-cpu-1.json) | 29.21 | 46.40 ms | 332 |
| [单通道 2](scalar-cpu-2.json) | 28.65 | 45.80 ms | 334 |
| [四通道 2](rgba-cpu-2.json) | 27.35 | 48.60 ms | 334 |

两轮均值 27.42→28.93 FPS，约 +5.52%；帧间隔均值 36.48→34.57 ms。运行中的世界存在两次绘制差异，系统后台负载没有完全隔离；只证明此场景的小幅改善，不代表所有场景或稳定 60 帧。四通道对照使用同一候选中的灰度读取着色器，因此这里比较的是缓冲格式，不是两套完整旧/新源码。

通过原生“继续下一段”进入静默飞船，V 切换第一人称、W 行走后，另一次 [1080p 采样](ship-first-person-cpu.json) 为约 23.6 FPS，人物 CPU 约 14.61 ms/帧、绘制提交约 14.36 ms/帧、1,029 次绘制/帧。没有飞船同镜头四通道性能基线，不能推算该场景提升。全部五份报告均为页面可见、无录制、WebGL error=0。人物分层计时是嵌套关系，不可相加。

## 画面对照

先用浏览器 JPEG 截图检查，再增加真正 PNG 帧导出，因为 JPEG 不能证明逐像素一致。JPEG 文件均使用 `.jpg` 扩展名。

暂停同一世界和相机，广场两次单通道原始 PNG 完全相同。切换四通道后，2880×1620 原始帧有 1.639% 的像素发生变化；平均每色道差值约 0.0062–0.0071/255，最大值 17/255，只有 54 个像素的任一色道差值超过 8。**不是逐像素一致**；相同半浮点精度与采样数量不保证不同附件格式输出完全相同，具体底层差异没有进一步归因。肉眼对照没有发现明显的色偏、几何变化或接触阴影消失。

- [广场单通道原始 PNG](raw-scalar-0.png)、[广场四通道原始 PNG](raw-rgba-2.png)、[像素统计](lossless-image-comparison.json)。此处重新加载后为“精致”档，实际渲染 2880×1620；不是上表性能测试的 1080p。
- [飞船单通道 PNG](ship-scalar.png)、[飞船四通道 PNG](ship-rgba.png)、[像素统计](ship-lossless-comparison.json)。实际 1920×1080、相机一致，589 个像素改变，最大 6/255，9 个像素超过 1/255。

广场群众肩背及袖口仍能看到原有肤色穿出，两个格式都有；人物服装问题没有在这次渲染优化中解决。飞船环境和电影还原亦未作为完成验收。

## 验证、发布与后续

原相关测试 16/16。新增三项先全部失败，修改后相关 19/19；覆盖实际目标格式、尺寸/精度、格式切换时附件重建及灰度/彩色调试输出。部署回归 75/75；共享、后端、客户端类型/构建通过，面板最终修改后单独客户端类型检查通过。

正式构建在独立 5200 服务实际接回飞船检查点，继续时间、W/D 行走、V 切换视角和暂停通过；页面加载 `index-CCOTDEXi.js`、没有开发面板，warning/error 为空。本轮没有做后端重启或完整战斗验收；没有改动存档逻辑。

发布只替换正式客户端，保留旧 JS。1,248 份候选输入中仅两份渲染/诊断源码改变；原有 11 份实验、800 份共享/后端编译产物和主服务 PID 83388 保持。85 份主记忆随世界自然更新，没有复制测试存档到主环境。见 [发布核对](publication.json) 与 [发布脚本](publish-client.py)。

QA 后端 PID 21471 和 Vite PID 21472 已核对命令、工作目录后停止，5200/5201 关闭，见 [停止结果](qa-stop.json)。临时浏览器尺寸恢复，测试页关闭；Codex 侧栏重新打开正式入口并确认新包，无开发面板或控制台警告/错误。

60 FPS 需要把单帧预算压到约 16.7 ms；当前约 34–42 ms 的场景仍差距明显。下一步以人物动画、实际几何绘制和更完整的连续游玩测量为重点；不以增加硬盘容量或服务器内存代替浏览器端优化，也不以本轮结果提出未经验证的最低硬件配置。
