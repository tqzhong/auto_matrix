# 暂停世界的重复同步修复

2026-10-19。本单元修复正式站试玩中发现的一项同步开销，不代表三部曲画面、剧情或持续流畅性已经验收。

## 证据和实现

- 正式站 tick 9195 暂停期间，25 秒只读 WebSocket 采样收到 473 次角色/车流更新，前三个数据包内容完全相同。消息累计约 2.22 MB 原始 JSON；该独立连接连同初始快照接收约 2.44 MB。五次探测往返 174–180ms，无超时。`before.json` 与 `sample.json` 保留结果；这不是浏览器 FPS 或完整输入延迟测量。
- 原来的 50ms 玩家同步定时器在角色仍被控制时持续广播，暂停不阻止重复状态进入发送队列。现在发送出口记住最近广播值：人物、世界字段、模拟刻均没有变化且没有事件/区块变化时，不再发包。
- 有效更新原样发送，保留同场人物和姿态时钟在同一个包中；不拆散角色组合。世界时间推进、原地属性变化、剧情切换、事件与置空字段仍发送。加入与重连的完整快照不受过滤影响，也不会消耗其他连接应收到的广播。
- 快速车流与完整 sandbox 快照共享比较基线，覆盖恢复旧车流、无车流存档与随后再次出现的车流。缓存保存序列化值，能识别原对象内部的改动，不持有可变对象作为比较依据。
- 沿用现有协议、模拟频率与依赖。代价是服务端保留最近状态字符串并执行比较；移动中的有效完整包仍保留，未声称解决所有网络或渲染瓶颈。

## 验证

- 改动前连接/帧率测试 8/8、隔离发布部署基线 54/54。重复同步复现先失败：预期一包，实际 21 包，见 `tests-before.log`。
- 中间时钟检查先失败，见 `clock-before.log`；已修复为世界时间变化时仍发包。
- 最终隔离部署回归 58/58，包括五项真实 Socket.IO 传输测试。覆盖重复暂停状态、连续移动、同场人物保留、死亡/控制权置空、数组替换、原地剧情改变、事件重复、车流恢复和第二客户端加入/重同步。
- 隔离副本核对 871 个源码与测试等文件，等于已提交 HEAD 加本单元两个文件；不含未完成的旧楼脱衣实验。三包类型与生产构建通过；客户端产物保持 `index-BQFlrsJM.js`，只有服务端同步逻辑改变。
