# 1-06 Lafayette：保留共享顶点与实际性能检查

2026-10-12，基于 `c82cf88`。只调整 Lafayette 静态几何的合批方式，保留上一轮墙板、窗户、帘布、拼花地板、壁炉与家具。**几何缓冲减少已验证，稳定帧率未通过；1-06、P0 与三部曲未高质量完成。**

## 改动与验证边界

原合批将有索引的家具展开成每个三角形三个独立顶点，重复提交软垫等表面的角点。Lafayette 改为使用项目已有 Three.js 的 `mergeVertices(geometry, 1e-6)`，先统一索引再按原材质合并。法线和 UV 参与共享判定，因此硬边及贴图接缝保持独立。其他场景保留原合批路径，没有新增依赖、资产、照明变化或剧情变化。

新增回归加载实际房间，逐个材质比较合批前后每个三角形的八个属性：位置、法线和 UV。三角形顺序、材质分配及数量相同，属性差异在 1e-5 内；固定家具/结构保持投射和接收阴影。旧代码首先失败，新代码通过。

| Lafayette 静态合批结果 | 旧展开方式 | 当前索引方式 |
| --- | --- | --- |
| 顶点数 | 774,000 | 238,095 |
| 几何缓冲字节 | 24,768,000 | 9,167,040 |
| 三角形数 | 258,000 | 258,000 |

原始未合批输入有 656,177 个顶点。当前合批数据来自最终测试诊断；旧方式的顶点数/字节数由同一房间的 774,000 个三角形角点、每角点 32 字节的 Float32 位置/法线/UV 推导，**不是直接测量整个 GPU 的显存分配**。顶点减少 69.24%，这些静态几何缓冲减少 62.99%，见 [计算记录](geometry-summary.json)。

最初尝试判断是否应沿用 Zion 的完整光照范围剔除，但真实对话机位的所有点光源范围都仍与视锥相交；试验测试要求隐藏灯光的前提不成立。该临时测试已撤回，原始 `lighting-before.raw.log` 保留本地。没有据此更改照明或称为灯光故障。

## 性能：尚未证明帧率改善

同一暂停 Neo 对话姿势 / tick 4670，1280×720、像素比 1.5，实际画布 1920×1080；关闭录制，预热 3 秒、采样 15 秒。所有样本的帧内提交均为 476 次绘制、3,324,716 三角形。

| 实际版本与采样 | FPS | p95 帧耗时 |

| [索引方式首次](performance-indexed-first.json) | 24.259 | 46.5 ms |

首次采样之间明显退步，后续交替对照中旧/新方式均只有约 22–23 FPS，不能据此声称此项改动解决了帧率，也不能把旧方式的 35.7 FPS 当作稳定基准。采样时没有录制或并发构建/测试，但机器状态和时间没有严格受控。结论仅限于已证明的几何缓冲减少，**渲染性能仍未达标**。没有降低像素比、阴影、人物或玻璃品质来换取数字。
