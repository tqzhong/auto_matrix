## 存档与更新

启用 `MATRIX_CLOUD_SAVE=supabase` 后，世界、剧情、时间控制和所有角色记忆在同一份 gzip 压缩快照中原子保存，数据库只保留当前快照。未配置云模式时继续使用原来的本地文件存档。

云存档连接失败、内容损坏或缺少密钥时拒绝以空世界启动。只有数据库成功返回“没有存档”才新建世界。保存沿用每 60 个模拟 tick、暂停/继续等控制边界、正常退出触发，并每 15 秒保存或续租；异常中断最多丢失最近一次成功保存后的进度。不要把断线等同于立即存档。

部署交接使用 `lease_until` 字段和递增版本号。发布支持此机制的代码前，先执行 `deploy/supabase.sql` 中的 `add column if not exists lease_until` 语句；原数据与权限不变。新实例先验证数据库并接受健康检查，随后等待旧实例保存、释放 45 秒租约，重新取得最后那份存档后才启动世界、发送完整快照和接收操作。等待期间 `/api/status` 的 `ready` 为 false，其他游戏 API 返回 503，浏览器保持连接等待；这不是已可游玩的状态。正常退出在最后保存后释放租约，异常退出等待过期；暂停时只更新续租时间，不重复压缩上传相同世界。版本条件仍阻止过期实例覆盖新进度。

首次从没有租约的旧版本更新时，以最后存档时间加 45 秒作为保护窗口；发布前暂停世界并保存备份。Render 会先路由新实例、再终止旧实例，因此更新期间可能等待约一分钟。不要将不支持租约的历史代码与新代码滚动交替；如必须回到旧版，先停服并保存当前存档，再处理租约兼容性。不会为交接购买付费服务。

每次上线更新：

1. 只提交已完成的改动，在不包含本地未完成实验的发布目录中运行相关测试、`npm run test:deploy` 和 `npm run build`，通过后推送 `main`。涉及存档格式或重大剧情迁移时，先暂停并导出云存档备份。
2. 检查 Render 是否收到推送；没有自动触发时由 Codex 发布最新已验证提交。等待控制台显示 Live，并核对提交 SHA。测试或构建失败时修复失败项，不跳过检查。
3. 检查线上双向操作回应、移动与相关交互，以及重启后的进度。更新会短暂断开连接，客户端自动尝试恢复上次确认的角色；不会自动抢回其他页面正在控制的角色。
4. 不得启动两个独立服务共同写入同一个存档。滚动部署由租约交接写入权；保存请求的响应丢失时，下次保存先核对那次确切的写入。若租约过期或确实发现另一实例的新版本，旧进程停止模拟并退出，避免持续运行无法保存的分支。需要在发布后观察日志、`ready: true` 和恢复状态，不能仅凭网页能打开或 Render 显示 Live 就宣布完成。

回滚代码仍读取当前云存档。需要恢复备份时先停止服务，保存当前行的副本，再明确选择备份恢复；不要在线覆盖仍在使用的存档。模型、音乐和代码更新不会自动重置数据库。
