# 黑客帝国三部曲制作方案

确认日期：2026-09-21。用户目标：覆盖三部曲关键情节，高质量还原电影场景；以 Neo 的生活、调查、觉醒、行动、选择和最终停战组成完整体验。

## 目标与范围

以 [剧情与玩法清单](trilogy-gameplay-audit.md) 的 **42 组剧情、102 个现有节点**为完整范围。清单中的“还缺什么”是制作要求，不是可忽略的备注。57 个场景定义是起点，不是美术完成数。

优先完成“墨菲斯联系 Neo → 电话指路躲避特工 → 成功脱身或被捕后重新接头 → 赴约见面 → 红蓝药丸”。随后完成第一部、第二部、第三部的所有关键事件，不以只做好大堂或序章替代完整目标。

矩阵中的日常生活采用正常城市的日夜与天气；办公室、住宅、夜店、构造体、飞船、锡安、机器城分别建立视觉风格。原片的绿色调是摄影风格的一部分，不能用统一绿色雨夜替代场景还原。

## 不可省略的制作标准

| 维度 | 验收要求 |
| --- | --- |
| 剧情 | 关键因果、人物身份、所在世界和事件先后正确；游戏原创分支明确标记；成功与失败不能导向互相矛盾的剧情 |
| 玩法 | 躲藏、追逐、驾驶、跳跃、救援、战斗、解谜分别有对应操作和世界反馈；定时文字不能代替这些机制 |
| 地图 | 路线、门窗、掩体、可达区域与视觉布景一致；可碰撞物体使用共享几何数据；关键空间有辨识度 |
| 美术 | 参考来源可追溯，逐场核对构图、建筑尺度、材质、道具、灯光、天气；在玩家实际视角检查，不只看固定展示镜头 |
| 人物 | 正确人物参与事件；动作与任务一致；死亡、感染、关系变化有持久结果；不能为布置下一场而任意复活人物 |
| 声音 | 现有电影原声按情绪匹配；对白提示、环境音和操作反馈不互相覆盖；关键对白可通过字幕理解 |
| 连续性 | Neo 主线接住日常存档；非 Neo 事件作为明确的另一视角；场景过渡保留状态；已完成剧情可回访但不改写当前世界 |
| 稳定性 | 成功、失败、重试、暂停、断线和保存恢复均可验证；角色被其他玩家占用时不抢占 |
| 性能 | 按当前场景加载/释放；重复物件合批或实例化；对实际浏览器帧率与资源占用进行检查 |

## 制作阶段

| 阶段 | 覆盖范围 | 核心依赖 | 完成证据 |
| --- | --- | --- | --- |
| P0 | 日常联系、办公室逃亡、审讯/成功逃脱、桥下接头、红蓝药丸 | 遮挡与巡逻、发现/失去目标、路线分支、接头状态、明确药丸交互 | 两种逃亡结果和红蓝选择均实际走通；测试保存恢复；办公室与赴约房间实机截图 |
| P1 | 第一部余下全部情节 | 训练与能力成长、追逐、团队救援、觉醒、剧情演出 | 第一部完整游玩与检查点验证；每组标记玩法/美术分别是否达标 |
| P2 | 第二部全部情节 | 程序/后门、复制体、冷兵器、驾驶护送、多队倒计时、飞行营救 | 钥匙匠保护、断电失败/补救、建筑师选择与 Trinity 营救可验证 |
| P3 | 第三部全部情节 | 循环空间、金色感知、舰船/APU、机器群、空中战斗、谈判与同化 | Mobil 到停战完整闭环；机器集体与建筑师身份正确；终局非普通清血条 |
| P4 | 电影路线后的原创循环 | 持久记忆、关系、异常与世界变化 | 新循环由本轮经历产生可观察差异，电影尾声与原创内容边界清楚 |

所有阶段沿用审计文档的节点 ID，避免重复创建同义任务或漏掉短小但关键的衔接事件。公共机制可以复用，人物动机、布景和任务规则按具体片段制作。

## 还原方法与取舍

继续使用项目现有 Three.js、共享状态和服务器验证，不更换引擎、不新增庞大运行依赖。优先为有明确玩法作用的环境建立共享布局，再增加材质、光照和道具，避免看似精细但人物可以穿过的场景。

参考资料与已有电影场景索引见 [实施记录](trilogy-scenes.md)。来源不完整的场景要标明待对照，不宣称已逐镜头核实。新做的渲染必须作为真正的 3D 环境服务游玩，不能把概念图当作已实现画面。

用户要求的是高质量还原。程序化原型、任务定义和自动化通关测试只能证明部分基础，不能替代高质量验收；没有实机证据的组不得标记为“全部完成”。
